Отлично! Давайте соберём всё, что мы разобрали, в **чёткий пошаговый алгоритм**. Я дам две версии: **концептуальную** (для понимания) и **практическую** (как в реальных библиотеках, с буфером).

# 📘 Часть 1: Концептуальный алгоритм (clustering variant)

Это версия «по одной точке», самая простая для понимания. Именно её мы использовали в примерах.

---

## 🔹 Входные данные

- **δ** — параметр сжатия (обычно 100–1000)
- **P** — целевой перцентиль (например, 0.90, 0.95, 0.99)
- **scale function** `k(q)` — например, `k₁(q) = (δ/2π)·arcsin(2q−1)`

## 🔹 Структура данных

```
C = []        # упорядоченный список центроидов
n = 0         # общее число обработанных точек
```

Каждый центроид — пара `(mean, weight)`:
- `mean` — среднее значение точек в кластере
- `weight` — количество точек в кластере

---

## 📥 ФАЗА 1: Добавление точки в поток

**Для каждой новой точки `x`:**

### Шаг 1.1: Обновить счётчик

```
n = n + 1
```

### Шаг 1.2: Если digest пуст — создать первый центроид

```
если C пуст:
    C = [(x, 1)]
    перейти к Шагу 1.7
```

### Шаг 1.3: Найти ближайший центроид

```
найти i, минимизирующий |C[i].mean − x|
```

Если несколько центроидов на одинаковом расстоянии — выбрать тот, у которого **больший вес** (это уменьшает число кластеров).

### Шаг 1.4: Проверить, можно ли добавить `x` в центроид i

Новый центроид после добавления:

```
new_weight = C[i].weight + 1
new_mean   = (C[i].mean · C[i].weight + x) / new_weight
```

Проверить правило размера в k-пространстве:

```
w_left  = сумма весов всех центроидов слева от i
q_left  = w_left / n
q_right = (w_left + new_weight) / n

Δk = k(q_right) − k(q_left)

если Δk ≤ 1:
    → можно добавить
иначе:
    → нельзя
```

### Шаг 1.5: Ветвление

```
если Δk ≤ 1:
    C[i].mean   = new_mean
    C[i].weight = new_weight
иначе:
    вставить новый центроид (x, 1) в C на правильную позицию
```

### Шаг 1.6: Проверить, не пора ли сжимать

```
если len(C) > δ/2:      # эмпирический порог
    выполнить СЖАТИЕ (см. Фазу 2)
```

### Шаг 1.7: Если нужен перцентиль прямо сейчас

```
перейти к Фазе 3
```

---

## 🔄 ФАЗА 2: Сжатие (merge)

Запускается, когда центроидов стало слишком много. Цель — уменьшить их число, не нарушая правило Δk ≤ 1.

### Шаг 2.1: Отсортировать центроиды

```
C = сортировка C по mean (возрастание)
```

### Шаг 2.2: Жадное слияние слева направо

```
новый_C = []
текущий = C[0]

для i от 1 до len(C)−1:
    кандидат = C[i]
    
    # пробуем объединить текущий и кандидат
    w_left  = сумма весов всех центроидов в новом_C
    q_left  = w_left / n
    q_right = (w_left + текущий.weight + кандидат.weight) / n
    
    Δk = k(q_right) − k(q_left)
    
    если Δk ≤ 1:
        # объединяем
        w_total = текущий.weight + кандидат.weight
        текущий.mean   = (текущий.mean·текущий.weight + кандидат.mean·кандидат.weight) / w_total
        текущий.weight = w_total
    иначе:
        # фиксируем текущий, начинаем новый
        новый_C.добавить(текущий)
        текущий = кандидат

новый_C.добавить(текущий)
C = новый_C
```

### Шаг 2.3: Повторять, пока число центроидов не перестанет уменьшаться

```
если len(C) уменьшилось на прошлом проходе:
    повторить Шаг 2.1
```

**На практике:** одного-двух проходов достаточно.

---

## 📤 ФАЗА 3: Извлечение P-го перцентиля

### Шаг 3.1: Отсортировать центроиды

```
C = сортировка C по mean (возрастание)
```

### Шаг 3.2: Посчитать центры масс

```
w_left = 0
для i от 0 до len(C)−1:
    q_i = (w_left + C[i].weight / 2) / n
    w_left = w_left + C[i].weight
```

### Шаг 3.3: Найти позицию целевого квантиля

```
q_target = P

найти i, такое что q_i ≤ q_target ≤ q_{i+1}
```

### Шаг 3.4: Интерполяция

**Случай A: q_target между двумя центрами масс (обычный случай)**

```
value = C[i].mean + (C[i+1].mean − C[i].mean) · (q_target − q_i) / (q_{i+1} − q_i)
```

**Случай B: q_target < q_0 (левый хвост)**

```
value = x_min + (C[0].mean − x_min) · (q_target − 0) / (q_0 − 0)
```

где `x_min` — минимальное известное значение (или C[0].mean, если неизвестно).

**Случай C: q_target > q_{last} (правый хвост)**

```
value = C[last].mean + (x_max − C[last].mean) · (q_target − q_last) / (1.0 − q_last)
```

где `x_max` — максимальное известное значение.

**Случай D: последний кластер — singleton (weight=1)**

```
value = C[last].mean    (точно, если q_target ≥ q_last)
```

# 📗 Часть 2: Практический алгоритм (merge-based, с буфером)

Это версия, которая используется в реальных библиотеках (Java, Python, ClickHouse). Она быстрее, потому что не пересчитывает k на каждой точке.

---

## 🔹 Структура данных

```
C      = []              # список центроидов
buffer = []              # буфер для новых точек
n      = 0               # общее число точек
B      = 10 · δ          # размер буфера (эмпирически)
```

---

## 📥 ФАЗА 1: Добавление точки

```
для каждой новой точки x:
    buffer.добавить(x)
    n = n + 1
    
    если len(buffer) ≥ B:
        MERGE()
```

**Всё!** Никаких проверок k на каждой точке. Очень быстро.

---

## 🔄 ФАЗА 2: MERGE (слияние буфера с digest)

### Шаг 2.1: Объединить и отсортировать

```
все_центроиды = C + [(x, 1) для x в buffer]
отсортировать все_центроиды по mean
buffer = []
```

### Шаг 2.2: Жадное слияние

То же, что в Фазе 2 концептуального алгоритма:

```
новый_C = []
текущий = все_центроиды[0]
w_left = 0

для i от 1 до len(все_центроиды)−1:
    кандидат = все_центроиды[i]
    
    q_left  = w_left / n
    q_right = (w_left + текущий.weight + кандидат.weight) / n
    
    если k(q_right) − k(q_left) ≤ 1:
        объединить текущий и кандидат
    иначе:
        новый_C.добавить(текущий)
        w_left = w_left + текущий.weight
        текущий = кандидат

новый_C.добавить(текущий)
C = новый_C
```

### Шаг 2.3: Оптимизация — вычислять `q_limit` один раз

Вместо вызова `k(q_right) − k(q_left) ≤ 1` на каждом шаге, можно вычислить:

```
q_limit = k⁻¹(k(q_left) + 1)
```

Тогда условие слияния: `q_right ≤ q_limit`.

Это **гораздо быстрее**, потому что `k⁻¹` вызывается один раз на кластер, а не на каждую точку.

## 📤 ФАЗА 3: Извлечение перцентиля

**Перед извлечением** — сделать финальный MERGE:

```
MERGE()
```

Затем — та же процедура, что в концептуальном алгоритме (Шаги 3.1–3.4).

# 📙 Часть 3: Псевдокод целиком

```python
# ============ НАСТРОЙКИ ============
δ = 100
B = 10 * δ

def k(q):
    return (δ / (2 * π)) * asin(2*q - 1)

def k_inv(k_val):
    return (1 + sin(2 * π * k_val / δ)) / 2

# ============ СОСТОЯНИЕ ============
C = []          # центроиды: [(mean, weight), ...]
buffer = []
n = 0

# ============ ДОБАВЛЕНИЕ ТОЧКИ ============
def add(x):
    global n
    buffer.append(x)
    n += 1
    if len(buffer) >= B:
        merge()

# ============ СЖАТИЕ ============
def merge():
    global C, buffer
    # 1. Объединить и отсортировать
    all_c = C + [(x, 1) for x in buffer]
    all_c.sort(key=lambda c: c[0])
    buffer = []
    
    # 2. Жадное слияние
    new_C = []
    current = all_c[0]
    w_left = 0
    
    for i in range(1, len(all_c)):
        candidate = all_c[i]
        
        q_left = w_left / n
        q_right = (w_left + current[1] + candidate[1]) / n
        
        if k(q_right) - k(q_left) <= 1:
            # объединяем
            w_total = current[1] + candidate[1]
            new_mean = (current[0]*current[1] + candidate[0]*candidate[1]) / w_total
            current = (new_mean, w_total)
        else:
            new_C.append(current)
            w_left += current[1]
            current = candidate
    
    new_C.append(current)
    C = new_C

# ============ ИЗВЛЕЧЕНИЕ ПЕРЦЕНТИЛЯ ============
def percentile(P):
    # финальное сжатие
    merge()
    
    # центры масс
    w_left = 0
    qs = []
    for mean, w in C:
        qs.append((w_left + w/2) / n)
        w_left += w
    
    # найти позицию
    if P <= qs[0]:
        # левый хвост
        return C[0][0]  # упрощение
    if P >= qs[-1]:
        # правый хвост
        return C[-1][0]  # упрощение
    
    for i in range(len(C)-1):
        if qs[i] <= P <= qs[i+1]:
            # интерполяция
            return C[i][0] + (C[i+1][0] - C[i][0]) * (P - qs[i]) / (qs[i+1] - qs[i])
```

# 📊 Часть 4: Сводная таблица шагов

| Фаза | Шаг | Что делаем | Сложность |
|------|-----|-----------|-----------|
| **1. Добавление** | 1.1 | `buffer.append(x)`, `n += 1` | O(1) |
| | 1.2 | Если буфер полон → MERGE | O(B log B) амортизированно |
| **2. MERGE** | 2.1 | Объединить C и буфер, отсортировать | O((δ + B) log(δ + B)) |
| | 2.2 | Жадное слияние с проверкой Δk ≤ 1 | O(δ + B) |
| | 2.3 | (опц.) Использовать `q_limit` | ускоряет в 5–20 раз |
| **3. Перцентиль** | 3.1 | Финальный MERGE | O(δ log δ) |
| | 3.2 | Посчитать центры масс | O(δ) |
| | 3.3 | Найти позицию P | O(δ) |
| | 3.4 | Интерполировать | O(1) |

# 🎯 Часть 5: Практические советы

### 1. Выбор δ

| Задача | δ | Память | Точность на хвостах |
|--------|---|--------|---------------------|
| Грубая оценка | 50 | ~400 байт | средняя |
| Стандарт | 100 | ~800 байт | хорошая |
| Высокая точность | 500 | ~4 КБ | отличная |
| Экстремальная | 1000 | ~8 КБ | максимальная |

### 2. Выбор scale function

- `k₁` (arcsin) — универсальная, используется по умолчанию
- `k₂` (log-odds) — лучше для экстремальных хвостов (q < 0.001)
- `k₃` (log) — лучшая изоляция выбросов

### 3. Размер буфера

```
B = 10 · δ    # эмпирическое правило
```

- Меньше буфер → чаще MERGE → медленнее, но меньше памяти
- Больше буфер → реже MERGE → быстрее, но больше памяти

### 4. Слияние нескольких digest'ов

```
def merge_digests(digests):
    all_c = []
    for d in digests:
        all_c.extend(d.C)
    all_c.sort(key=lambda c: c[0])
    # тот же жадный алгоритм
```

### 5. Чего избегать

- **Не вызывайте `k` на каждой точке** — используйте буфер
- **Не сжимайте слишком часто** — это дорого
- **Не используйте δ < 20** — точность на хвостах будет плохой
- **Не забывайте про финальный MERGE** перед извлечением перцентиля
